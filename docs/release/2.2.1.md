# 2.2.1: neutral values respect the configured axis lists

This patch corrects a real parameter-resolution defect reproduced against the
public **2.2.0** distribution. Its baseline is main/release commit
`5067611b9252ca9f8b6023e1f05dfeb67ad28c16`; the earlier 2.1.2-to-2.2.0 work is
separate and is not counted as this patch's improvement.

## Defect and correction

The searcher passes indices into `MetaAxisSpace.reasoning_profiles` and
`output_budgets`. In 2.2.0, `neutral_params()` instead used global enum ordinals.
For the default reasoning list `[OFF, STANDARD, DEEP]`, the global STANDARD ordinal
2 selected DEEP. The parameter specification advertised index 1, so the two
neutral surfaces also disagreed. Singleton `[STANDARD]` / `[MEDIUM]` spaces are
valid configuration, but their only valid index is 0; the old neutral values 2/1
caused guarded evaluation to fail before any provider request.

Both surfaces now choose the index of STANDARD/MEDIUM in the configured lists,
or index 0 when that preferred value is excluded. Explicit optimizer integers
retain their existing meaning: positions in the configured `MetaAxisSpace`
lists, not the global `REASONING_ORDINALS` / `OUTPUT_BUDGET_ORDINALS` helper
mappings. A custom list order defines its raw index meaning. Guarded bounds
checks stay enabled.

| Offline probe | Public 2.2.0 | 2.2.1 |
|---|---|---|
| Default neutral request | unintended DEEP / MEDIUM | STANDARD / MEDIUM |
| `[STANDARD]` / `[MEDIUM]` | bounds error | STANDARD / MEDIUM |
| Reordered `[STANDARD,DEEP,OFF]` / `[MEDIUM,LARGE,SMALL]` | OFF / LARGE | STANDARD / MEDIUM |
| Preferred value excluded: `[OFF,DEEP]` / `[LARGE]` | bounds error | OFF / LARGE |
| Default reasoning plus singleton `[MEDIUM]` | budget bounds error | STANDARD / MEDIUM |

These are deterministic development regressions with local providers, not model
quality or runtime-speedup measurements. The probe inspects the actual generated
`ProviderRequest` fields; regression tests also execute the real calibration
engine through Python runtime, CLI `--space` and MCP `tuning.space` paths. A
failed preflight measurement still produces a saved `REQUIRES_MANUAL_REVIEW` /
`hold` artifact. With `--fail-on-gate`, that completed CLI run exits 1.

```bash
python -m pytest tests/test_neutral_subset_parameters.py -q
python -m pip install "omegaprompt[mcp]==2.2.1"
```

## Compatibility

Existing artifact schema 2.0, CLI aliases, MCP tool names and explicit search
indices are unchanged. Historical artifacts remain as observed. **Fresh default
baseline runs can change** because they now use STANDARD rather than DEEP; this
can affect provider requests, costs, stress rankings and calibration outcomes.
Re-run a declared comparison instead of treating old and new baselines as equal.

The five generated reference cases change only their raw
`neutral_baseline_params.reasoning_profile` from 2 to 1, and their manifest hashes
are regenerated accordingly. Their metrics, threshold values, classifications
and ship/block outcomes are unchanged. The 2.2.0 tag preserves the old snapshots;
no historical artifact is rewritten in place.

The `noise_floor` field description now names its existing unit correctly:
absolute fitness standard deviation, not variance. This changes documentation,
not the value or schema field. The composite Action description now describes
declared artifact/gap/hard-gate checks and stays within the Marketplace limit of
125 characters; a passing artifact gate is not a generalization proof.
