# 2.2.0: evaluation integrity and bounded work

Baseline: public 2.1.2, commit `fcc326aa2f08d76e576e57add1023adb7c3df63f`.
All measurements below use deterministic local counting providers on Python
3.12 / Windows, without paid API calls. They concern implementation behavior,
not model quality or production generalization.

| Workload | 2.1.2 | 2.2.0 | Meaning |
|---|---|---|---|
| Change one input after a 3-item evaluation | 0 new calls; stale result reused | 3 target + 3 judge calls | Context is reevaluated |
| Repeat unchanged resolved configuration | 0 new calls | 0 new calls | Replay adds no independent observation |
| 2,000 items, 4 workers | all 2,000 futures submitted before consumption | at most 4 outstanding results | Same 4,000 target/judge calls and input order |
| First judge call raises after target succeeds | completed-run accounting omitted both attempts | 2 attempts, returned target usage retained | Partial failure remains an exception, not a success artifact |
| Shared IDs declared disjoint | correlation skipped; gap could pass | ValueError / calibrate exit 2 | Contradictory mode cannot bypass pairing |

Reproduce with `python -m pytest tests/test_evaluation_integrity.py
tests/test_memoization.py tests/test_parallel_determinism.py tests/test_walkforward.py`.
These are observed development regressions, not a blind accuracy benchmark.
No elapsed-time speedup or total-memory claim is made. Results still retain
item outputs; only intermediate queued work is bounded. Context fingerprint
construction scans dataset/rubric/variants on each evaluation and adds CPU
cost to cheap mock workloads.

## Cache and failure contracts

`PromptTarget.evaluate(params)` reuses an observation only within the same
dataset, rubric, variants, axis space, profile, provider/judge instance and
declared model/base URL. Public context changes clear cached observations and
selection history, while cumulative costs remain. Changing opaque custom
backend state requires `target.clear_cache()` or `evaluate(params,
use_cache=False)`. Returned cached results remain mutable for compatibility;
do not edit them. Configuration mutation during a pass and concurrent
evaluate calls on one instance are unsupported. Item workers require thread
safe provider and judge implementations.

`total_api_calls` counts target/judge adapter attempts, including exceptions.
`last_usage` includes usage actually returned by adapters, including work
before a later failure. `failed_evaluations` records failed status, elapsed
time, attempted calls and returned usage. Hidden provider retries and costs
that an adapter never returns remain unknown. Failed runs raise and produce
no completed EvalResult or calibration artifact.

## Validation and compatibility

CalibrationArtifact schema remains 2.0. Historical artifacts are read with
their existing meaning. `auto` retains historical shared-ID correlation
behavior; callers must inspect actual data and its selection history.
Explicit `disjoint` rejects overlapping IDs, including before provider calls
in runtime calibrate. Paired replay measures repeat consistency on the same
cases; it does not demonstrate unseen-input performance. Disjoint holdout
retains aggregate gap and hard-gate checks without inventing a correlation.
Neither a high Pearson nor a small gap guarantees absolute quality.

PreflightReport adds `measurement_status` and `probe_accounting`. Empty maps
mean unknown historical measurement state. A failed or insufficient measured
probe requires manual review when deriving an adaptation plan. The runtime
applies min_kc4, max_gap, unlock_k and manual review. Rescoring, candidate
budget caps, schema fallback, skip_axes, ensemble shifts, rubric overrides
and cache scheduling remain advisory-only and are reported that way.

`runtime.classify_traps` / MCP accepts optional validation_mode; paired
classification requires the newer mini classifier, and content mismatch or
partial overlap remains a blocker. Older mini releases work with default
auto mode. CLI `omegaprompt` and `omegacal` aliases are retained. Gate exit 1
and input-error exit 2 remain distinct.

Upgrade: `python -m pip install "omegaprompt[mcp]==2.2.0"`.
The exact tested multi-package combinations and public-download verification
are recorded in the release evidence after publication.

2.2.0 runtime split contract: explicit paired mode requires matching ID sets and identical input/reference content on at least three cases; explicit disjoint mode rejects overlapping IDs or exact duplicate input content before provider calls. Historical auto mode is retained and does not establish independence.
